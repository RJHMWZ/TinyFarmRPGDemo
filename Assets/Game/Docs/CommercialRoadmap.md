# Tiny Farm 商业项目演进路线

## 当前已经落地

- `Boot -> MainMenu -> GameScene` 明确区分启动、前台流程与游戏运行时。
- `GameRoot` 持有跨场景服务；功能面板以预制体进入 `UIPanelCatalog`，不散落在场景中。
- UI 具备分层、缓存/常驻/临时生命周期、返回栈、输入模式和所有者式暂停机制。
- 存档使用版本化信封、临时文件原子替换、备份恢复和旧角色档案迁移。
- 角色外观与名字使用数据资产；外观数据库只在对应资源变化时自动重建。
- Runtime、Editor、EditMode Tests、PlayMode Tests 已拆分程序集。
- 项目健康检查会在正式构建前执行；命令行脚本可统一运行测试与健康检查。

## 当前语言边界

本阶段只启用英文。默认 locale 必须为 `en`，随机名字只从英文池产生。中文名字池可以保留在数据资产中，但在完整引入语言服务、文本表、字体回退和存档语言设置以前，不接入运行时入口。

## UI 内容接入规则

`UIPanelCatalog` 当前允许为空，因为尚未出现实际游戏内功能面板。添加背包、任务、地图、关系、商店或设置时：

1. 面板制作成独立预制体，并继承 `UIPanel`。
2. 只在场景里保留 `UIRoot`、相机、地图和确实属于场景的对象。
3. 在目录中配置层级、生命周期、隐藏 HUD 和暂停策略。
4. 通过 `UIService.Open` 打开，不由业务系统直接实例化。
5. 为关键打开/关闭流程补 PlayMode 测试。

标题菜单、存档选择和创建角色属于 Frontend 流程，不强行注册为游戏内面板。

## 下一批商业化优先级

### P0：形成可玩的垂直切片

- 完成时间/日期、交互、物品、背包、耕种、生长、采集和最小经济闭环。
- 为每个系统明确数据模型、运行时服务、表现组件与存档段，避免逻辑写进 UI。
- 先完成一张可反复游玩的地图，再扩展多场景与内容量。

### P1：内容生产与稳定性

- 为物品、作物、配方、NPC、任务建立带稳定 ID 的 ScriptableObject 数据库和校验器。
- 给存档迁移增加逐版本测试、写入校验和异常恢复提示；自动存档采用轮换槽位。
- 建立资源预算：纹理尺寸、图集、音频压缩、场景对象数、内存峰值与加载时间。
- 内容明显增大或需要按区域卸载时，再引入 Addressables；不要为当前小体量提前增加部署复杂度。

### P2：发布能力

- 确定首发平台后再接入成就、云存档、手柄规范、商店 SDK 和崩溃上报。
- 在对应平台真机验证文件路径、存档原子替换、暂停/焦点恢复和分辨率适配。
- 将 `Tools/CI/Run-UnityValidation.ps1` 接入 CI runner，并补目标平台 Development Build 与冒烟测试。

### P3：本地化

- 核心文案稳定后统一接入本地化系统，不在各面板里维护散落字符串。
- 同一阶段完成英文/简体中文文本表、字体 fallback、动态布局、语言选择与缺失键检查。
- 名字池跟随语言服务选择；旧存档中的玩家姓名保持原样，不因切换语言自动替换。

## 验收门槛

每次结构或存档变更至少满足：脚本编译通过、EditMode 测试通过、PlayMode 测试通过、项目健康检查通过。进入正式内容生产后，再增加目标平台构建、启动到主菜单、载入存档和进入游戏场景的自动冒烟测试。
